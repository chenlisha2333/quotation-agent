# 需求增量：有来源的候选资料检索与只读工具调用

> 此文记录 v0.4.0 的历史范围。当前六款官方产品事实与四个只读工具见[新版需求增量](需求增量-官方施耐德产品RAG与型号工具.md)。

版本：v0.4.0；日期：2026-10-22。承接[自然语言与 Word 需求](需求增量-自然语言与Word导出.md)。报价规则、审批权限和导出字段不变。

## 业务目标

用户询问施耐德候选产品时，助手先读取本仓库已记录的型号、规格、外形尺寸和官方页面链接，再回答并展示资料来源；询问当前任务时，模型只能通过白名单只读工具获得当前角色可见的状态。知识库没有的正式选型、供应商人民币价格、税或 CAD 安装结论，必须留给人工核实。

## 验收条件

| 编号 | 条件 | 证据 |
|---|---|---|
| RAG-01 | 只检索 `templates/施耐德询价表示例.xlsx` 的三款候选型号，结果包含型号、片段和 HTTPS 官方链接 | 检索测试覆盖型号、尺寸、无关问题 |
| RAG-02 | 无匹配时不生成伪造来源；产品数据标明“候选，待技术确认” | `search_knowledge()` 返回空列表；页面仅显示真实命中来源 |
| TOOL-01 | Responses API 仅声明 `get_current_task_summary`、`search_product_knowledge` 两个严格参数模式的函数 | 请求体和模拟调用测试 |
| TOOL-02 | 服务端拒绝未授权工具、畸形参数和超过两次工具调用 | 白名单分派与错误处理测试 |
| TOOL-03 | 任务 ID 和身份由 API 确定，模型参数不能选择任意任务或文件路径；技术角色的成本与销售金额不在工具结果中 | 角色过滤、任务版本不变测试 |
| UI-01 | 模型回复下面显示候选资料链接，用户可核查 | 页面 `appendSources()` 用 DOM 文本节点和固定来源 URL |

## 数据流与边界

问题 → 本地词项检索（最多 2 条） → 带来源片段的 Responses 请求 → 模型可选择函数调用 → 服务端校验名称和参数 → 返回当前任务摘要或再次检索 → 模型回答。最多执行 2 次工具调用；`store=False`，续接时回传上一轮输出及对应 `function_call_output`。初始请求只附任务 ID，任务摘要仅在模型调用任务工具后发送。

资料来自原有示例 Excel，而不是自动抓取实时网页；三个型号只是技术选型候选。检索不涉及价格表、真实客户文件、网络爬取或自动补价。来源链接不代表当前价格、在售状态、安装可行性或公司批准。旧 `rag_module.py` 依赖未安装、没有进入主流程，已移除，避免把实验代码误认为可用功能。

## 后续扩展条件

拿到经许可的施耐德产品主数据和企业知识资料后，先建立脱敏评测集，记录召回率、错误引用、拒答质量和人工修正量，再决定是否引入向量索引。供应商价须由独立的采购核准流程进入结构化价格库，不能从 RAG 文本直接参与报价。
