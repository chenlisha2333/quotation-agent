## 1. 背景、目标与成功标准

电气零件报价需要从客户询价核对型号、寻找有凭证的采购价、计算销售价、审核并生成客户文件。错用品牌/型号、使用过期或无来源价格、金额口径不一致、对外泄露成本，都可能造成实际损失。本项目先完成**限定范围内可核对、可恢复、可追溯的报价闭环**，再扩展非结构化询价与 CAD。

首期目标：给定字段明确的 Excel 清单，报价经办人可为新任务选择价格来源。本地价格库查询和人工录价路径当前可用；网页或外部软件/ERP需适配器与业务授权，接入前必须明确提示且不得静默切换来源。当前报价政策仍仅对符合施耐德限制的明细查询合格人民币成本；缺价由人补齐；确定性程序计算草稿；顺序审批后从冻结快照导出客户 Excel 或 Word。自然语言窗口帮助查询任务和候选产品资料，不代替选型、核价或审批。

业务成功须在企业提供的脱敏真实案例上证明：关键字段正确、错配被拦截、金额与人工核准结果一致、客户文件无内部成本、操作与版本可追溯。当前没有人工基线、真实供应商报价或企业签核，不填写“效率提升百分比”等结果。

## 3. 用户、职责与权限

| 角色 | 需要完成的事 | 当前边界／缺口 |
|---|---|---|
| 报价经办人 | 上传清单、查看状态、处理澄清、生成草稿 | 本机页面可操作；正式岗位和项目归属待定义 |
| 技术审核人 | 核对型号、规格、品牌与选型依据 | 有 `technical` 审批关卡；无正式产品主数据 |
| 采购审核人 | 核准成本凭证、有效期和供应商条件 | `procurement` 可补价与审批；税/交期/阶梯价不完整 |
| 商务审核人 | 核准定价规则、条款与客户发布 | `commercial` 为最后关卡；正式规则与模板待签核 |
| 管理员/数据负责人 | 账户、密钥、备份、留存与审计 | 仅本机令牌和 SQLite 事件；企业身份待开发 |
| 结构/CAD 工程师 | 核对尺寸、审核布局 | 只有虚构尺寸的离线矩形原型；无工程审核工作流 |

`QUOTE_APPROVERS_JSON` 配置本机角色令牌；技术、采购、商务须由不同操作者顺序审批并写意见。未配置令牌时部分本机草稿接口可访问，正式审批不可用。这不是企业单点登录或完整权限系统。成本、销售价和客户导出按角色限制；接入真实数据前必须补企业身份、任务级授权、密钥管理与留存规则。

## 4. 当前业务流程与数据流

```text
客户 Excel
  → FastAPI 上传（文件类型和大小检查）
  → pandas 解析、Pydantic 产品字段
  → 施耐德品牌/型号规则；不满足则修正清单重传
  → 本地价格按型号/规格/单位/CNY/来源/有效期/核准状态过滤
  → 缺价按 item_id 由采购人工补齐；有价还需核查
  → LangGraph 固定流程调用 Decimal 金额计算
  → SQLite 任务快照和操作事件；可恢复
  → 内部草稿 Excel / Word
  → 技术 → 采购 → 商务审批，并满足定价规则闸门
  → 冻结第 1 版 → 客户 Excel / Word

页面自然语言问题 → 官方产品事实检索 → 可选模型与四个只读工具
                   → 回答及来源；不回写报价和审批
```

价格库不可读取或存在无法解码的价格记录时，上传返回 HTTP 503，安全删除本次临时询价文件，并且不创建报价任务或事件；正常查询成功但没有合格价格时，仍进入采购人工补价。数据库故障细节只记入受控日志，不返回文件路径或底层数据库错误。

任务状态“完成”只说明明细可计算，不等于商业批准；客户版必须取审批后的冻结快照。模型未配置时问答返回明确错误，报价主流程仍可运行。当前无客户报价第 2 版、作废或发送记录。

### F16 的 Text-to-CAD 产品边界与验收

- **用途**：根据系统生成的结构化 `DesignSpec` 辅助产生一个指定柜型的二维安装板布局初稿，减少工程师从零摆放元件的重复工作。它不是报价依据，不负责决定产品选型、价格或工程规则。
- **输入**：已审核的 `BOMSnapshot`、柜型/安装板尺寸、元器件二维外形和安装孔/方向信息、禁布区域、最小间距等经工程师确认的约束。缺少关键尺寸或规则时停止生成并列出缺项，不让模型补猜。
- **输出**：带任务、BOM、产品主数据、规则和生成器版本关联的二维 DXF 初稿及预览；记录各元件位置/方向、尺寸来源、提示或结构化请求摘要、校验结果和人工修改。输出始终标记“待工程审核”。
- **生成边界**：T14 固定核查 [Youssef-RAPCorp/cad-agent](https://github.com/Youssef-RAPCorp/cad-agent) commit `f5e3fec5629347f8e9c6e9b2fc3dd0a607e2eeb4`。其 DrawingSpec 的矩形 schema 可被本项目 `app/cad_agent_adapter.py` 转换为 BOM 布局提案，并通过现有合成几何校验；这是对适配器输入契约的验证，不是候选 LLM 输出质量验证。候选模型生成、Python 3.13 兼容、许可审查、依赖安全和 OS 隔离仍待验证。只有固定版本候选实际输出能稳定通过独立校验器，才考虑接入；否则保留确定性布局基线。
- **代码执行安全**：优先让模型输出受 schema 校验的布局数据，由服务端确定性 DXF 生成器绘图。若所选开源方案必须执行生成代码，则代码只能在无网络、无凭证、无宿主目录写权限、CPU/内存/运行时限额的隔离环境运行，并限制可用 API；越权、超时或解析失败即拒绝产物。CAD 校验器只处理生成文件，不执行其内容。
- **确定性验收**：检查文件可解析、所有必需 BOM 项及数量一致、元件均在安装板有效区域内、无几何碰撞、满足已确认间距并避开禁布区；不满足时标明具体错误且不得标记为通过。自动修复只能在有界次数内运行，每次修复后重新执行全套校验。
- **人工与业务验收**：通过机器校验不代表可制造或可投产。结构/电气工程师必须审核并记录通过、退回及修改原因。任何正式图纸均不得由系统自动发布或直接用于生产。若审核修改了 BOM 或影响报价，创建新报价版本并重新审批；纯布局变更也要生成新 CAD 版本并保留前版。
- **范围排除**：第一版不含接线图、原理图、通用柜型、三维 CAD、自动电气选型、制造文件和无需审核的生产图。评价指标至少包括 DXF 生成成功率、硬约束错误率、首次通过率、修复后通过率、工程师审核通过率及人工修改量；无真实工程师审核集前不报告业务准确率或效率收益。

## 6. 数据与金额契约

`Product` 保留任务内 `item_id`、名称、型号、规格、品牌、数量、单位；Excel 解析现在要求有产品名的行数量为数值单元格中的有限正整数，并拒绝超过 15 位的 Excel 精确整数范围。该限制用于避免表格精度丢失，不是企业最大订购量。`PriceRecord` 成本是 `Decimal`，有 SQLite 稳定记录 ID；自动采用还要核对产品属性、`CNY`、`source_reference`、`valid_until`、`verified` 和 `price_precision=decimal_text`。报价项和冻结快照保存价格记录 ID、来源凭证标识、有效期、证据状态及原有定价规则 ID，因此后续价格记录变化不会改写旧报价的这些来源字段。人工补价标记为“待采购凭证”，不能伪装为已核准供应商价。上传原件以随机文件 ID、受控扩展名和 SHA-256 关联任务；不保存客户原始文件名或绝对路径。施耐德官方产品页只是候选资料出处，**不是供应商成本或采购核准**。

当前草稿规则 `draft-cost-times-1.2-v1`：

```text
销售单价 = ROUND_HALF_UP(人民币成本价 × (1 + 0.20), 0.01)
行金额   = 销售单价 × 正整数数量
整单金额 = 各行金额之和
```

合成例：成本 `¥10.00`、数量 `2`，销售单价 `¥12.00`，行金额 `¥24.00`。20% 是**成本加价率**，不是 20% 毛利率。税、折扣、运输、辅材和人工的范围尚未确认，规则只能作为草稿口径。若企业确认另一口径，必须有新规则版本、手算样例和回归测试，不能静默修改旧快照。

SQLite 保存任务快照、操作事件和已发布第 1 版。第 1 版不可覆盖；报价行已保存采用的价格记录 ID 与凭证快照，任务保存询价原件 ID、扩展名和哈希。当前仍没有供应商价格版本审批、原件留存期限/备份策略、发送状态或报价第 2 版。正式验收须能从客户金额追溯到明细、成本凭证、规则、审核人与文件版本。

## 7. AI、RAG 与工具调用边界

LangGraph 报价主链是**确定性工作流**，不能因为使用 LangGraph 就声称模型自主定价。模型只在问答分支工作。当前 RAG 从 `data_sources/schneider_products.json` 检索六款经核对的施耐德官方产品事实，返回片段、产品/数据表链接和核对日期；没有向量数据库或企业知识库。`get_current_task_summary` 读取当前会话任务的角色过滤摘要，`search_product_knowledge` 搜索资料，`get_product_details` 按完整型号查事实，`compare_product_models` 确定性列出差异。工具白名单、参数和最多两次调用由后端控制；模型不能指定任意任务 ID、文件路径或写入工具。

AI 验收分别检查来源准确、无资料时承认未知、成本与客户数据角色隔离、越权工具拒绝、模型失败不影响报价。真实模型运行和企业外部传输许可尚未验证。即使后续增加资料检索与抽取，型号、价格、税额、工程尺寸和发布仍须确定性校验及人工确认。

## 10. 实施顺序与完成定义

1. **修复输入边界并冻结技术基线**：明确数量为正整数时拒绝小数和缺失值，增加回归测试；补真实浏览器、目标 Word/Excel、Docker 和真实模型实机检查。此步只证明原型运行。
2. **建立业务金标准**：取得经许可的脱敏询价、施耐德主数据和采购价；技术/采购逐行标注型号和价格可用性。没有数据不扩大自动匹配结论。
3. **确认财务与审批**：企业手算样例确定税、成本范围、加价和舍入；实现规则版本与审批矩阵，在冻结集逐项对账。`QUOTE_APPROVED_RULE_ID` 只是程序闸门，不是书面签核。
4. **补报价生命周期**：退回、变更新版、作废、发送、企业身份、任务级授权、备份恢复和多用户演练。
5. **扩展智能**：先评测当前 RAG/工具的来源与越权行为，再用授权资料扩检索；拿到真实非结构化询价与字段答案后才开发 AI 抽取。
6. **单独启动 CAD**：工程师确认柜型和安装约束后先做确定性二维布局及校验，再考虑受控生成/修复；影响 BOM 或成本必须新建报价版本并重审。

原型完成定义：有代码、可复现测试、失败处理和对应教学文档。当前 CAD 代码只达到合成布局原型阶段，尚未达到 F16 工程原型验收。业务试点完成定义：有脱敏冻结集、人工正确答案、差异清单和责任人签字。正式上线另需身份、权限、备份、安全、模板与规则签核。**125 项自动测试通过不等于企业报价准确率达标。**

拿到数据后再设指标阈值：字段准确率＝正确字段数/标注字段数；硬约束误接受率＝错误自动接受行数/自动接受行数；金额一致率＝与签核样例一致的报价数/评测报价数；来源可追溯率＝能定位到有效凭证的采用价格行数/采用价格行数；人工处理时长从收到询价到可提交审批计时。每项记录样本量、适用范围和人工裁定方式。
