# 12 自然语言只读助手

## 业务目标：先明确为什么

用户能在报价页面问“当前任务卡在哪里”“这行为什么待补价”。自然语言可降低查阅任务字段的门槛，但模型可能猜测，因此它只解释**已有任务摘要**，不得决定成本、生成正式报价、审批或修改任务。已有价格计算和审批代码仍是唯一执行路径。

## 技术、简单解释和专业定义

**必须掌握：** FastAPI 接口接收问题；Pydantic 模型验证长度与结构；HTTP 客户端向模型发送请求；现有角色过滤保护成本字段。简单说，API 是前端和后端约定的“窗口”，Pydantic 是进入窗口前的“表单检查”。专业地说，API 是 HTTP 契约，Pydantic 是运行时数据校验与序列化层。现在还接入了六款官方产品事实检索和四个只读函数；详见教程 15、16。**可暂缓：** 多模型路由和流式输出。

## 为什么这样实现，与模块关系及数据流

网页 `static/index.html` 的 `sendChat()` → `POST /assistant/chat` → `app/main.py:chat_with_assistant()` → `get_task_state()` 读 SQLite → `_task_response()` 按技术/采购/商务角色过滤 → 取最多 30 项的摘要。`app/assistant.py:answer_question()` 先调用 `app/knowledge.py:search_knowledge()` 检索候选资料；模型只有调用 `get_current_task_summary` 时才收到已过滤的任务摘要。技术角色的成本、单价、金额在 `_task_response()` 已置为 `None`，模型也收不到它们。AI 回复用 `textContent` 显示，避免把模型文字作为网页代码执行。接口没有 `save_task_state()`、补价或审批调用，问答不会推进任务版本。

## 核心代码逐段解释

1. `ChatTurn` 和 `ChatRequest` 声明字段类型及长度：问题最多 1000 字，历史最多 6 条。这是资源边界；`history` 由本页暂存，切换任务时清空。
2. `chat_with_assistant()` 首先调用 `authorize()`，若传入任务 ID 就读取任务，并从 `_task_response()` 的结果取状态、币种和明细。不传任务 ID 也可问一般操作问题，此时上下文为“无关联任务”。
3. `answer_question()` 从 `OPENAI_API_KEY` 与 `OPENAI_MODEL` 读取配置；`_responses_url()` 要求 HTTPS；请求包含 `instructions`、`input`、`tools`、`max_output_tokens=600`、`store=False`。`INSTRUCTIONS` 明确检索与任务资料只是数据，不能作为新指令。最多执行两次工具调用。
4. `_output_text()` 遍历 `output` 中的 `message` 与 `output_text`，因为响应可能先含其他类型。超时和服务故障变为 502；配置缺失变为 503。日志不写密钥或问题正文。

## 必须掌握的 Python 基础

函数参数的 `str | None` 表示可以是文字或空值；`list[ChatTurn]` 表示列表元素类型；`try/except` 把外部故障转成可理解的错误；`async def` 和 `await` 让网络等待不阻塞同一事件循环。先理解这些，再看 `httpx.AsyncClient` 的细节。`dict` 只存当前请求的数据，不等于数据库记录。

## 实际运行与测试

本机先安装依赖并设置 `OPENAI_API_KEY`、`OPENAI_MODEL`，运行 `python run.py`，打开 `/static/index.html`，输入问题。没配置模型时页面会显示 503 提示，上传和导出仍可用。自动测试：`.venv/bin/python -m pytest -q tests/test_chat.py`。测试以 `httpx.MockTransport` 模拟模型响应，验证技术角色工具结果中的价格字段为空且任务版本不变；没有调用真实模型。

## 常见错误与排查

- 503：检查两个环境变量是否在**启动服务的进程**中，而不只是写在 `.env`；本地启动不会自动读 `.env`。
- 502：模型超时、地址错误或服务未返回文字；检查 HTTPS 根地址和服务日志，不把 API Key 贴进日志或聊天。
- 404：任务 ID 不存在；在页面重新加载任务。
- 回答与业务数据不符：核对任务版本、角色可见摘要与原始记录；模型回复不能替代报价审核。

## 面试可能问

**为什么不让 LLM 直接改价？** 金额需可复算、可审计、可审批；模型仅解释，`pricing.py` 的 `Decimal` 规则决定金额。**为什么再次在后端过滤？** 前端隐藏不是权限控制；模型上下文必须由服务端根据令牌构造。**如何降低提示注入影响？** 检索片段标记为只读数据、模型只得到四个白名单只读工具；仍需人工核实模型文本。
