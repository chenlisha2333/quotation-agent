# 模块 2：价格查询、核查与金额（第一轮开发后）

更新日期：2026-10-21。这里重点讲金额链路；产品匹配详见[模块 3](07-人民币与施耐德产品匹配.md)，最新 1.2 倍规则和询价表见[模块 10](10-施耐德询价表与1点2倍报价.md)。当前规则由用户指定，但税、舍入和企业签核尚未正式确认；客户版导出已有本机审批闸门。

## 业务目标：为什么先改金额

报价单上的“单价 × 数量”必须等于行价，所有行价之和必须等于合计；还要知道每一行用了哪个成本、来源和计算规则。原实现用 `float`，先从未舍入单价计算行价，再分别舍入，可能出现单价 0.33、数量 3、行价 1.00。本轮改成十进制计算，先把单价舍入到分，再乘整数数量，得到 0.99。

**简单理解**：`Decimal` 像按十进制写在纸上的数字，适合按“分”处理价格。**专业定义**：Python `decimal.Decimal` 是十进制浮点类型；`quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)` 按指定量级和规则舍入。它只保证代码按已设规则确定地计算，**不能替企业决定规则是否正确**。

## 核心技术、方案和理由

| 技术 | 在本项目的作用 | 选择理由与边界 |
|---|---|---|
| `Decimal` | 表示成本、加价率、折扣、单价与行价 | 避免在业务计算中使用二进制浮点；来自旧库和网页的历史精度无法自动恢复 |
| Pydantic | `PriceRecord`、`QuotationItem` 等模型检查字段 | 让模块之间用同一数据契约；金额在 JSON 中作为字符串传递 |
| SQLite `price_decimal TEXT` | 保存新价格的十进制原文 | 在现有 `price REAL` 表上增列即可兼容旧数据，避免破坏已有库；旧 `REAL` 列仅用于兼容 |
| 固定规则 ID | 默认记录 `draft-cost-times-1.2-v1` 和 `ROUND_HALF_UP`；自定义参数使用不同 ID | 让报价项可说明“按哪版规则算”；不能悄悄改旧版本含义 |
| pytest + openpyxl | 验证边界金额、接口、工作流和导出 | 让计算结果可复现，核对导出原文与显示值 |

用户已指定默认“成本 × 1.2”，对应现有“成本 × (1 + 加价率) × 折扣”公式中的 `加价率=0.20`、`折扣=1`。尚未加入税、多币种或毛利率换算。折扣限制在 0～1、加价率不得为负；其他业务规则要另建版本。

代码和 API 的字段名仍叫 `profit_rate`，这是兼容旧接口的命名；它在当前公式中**按加价率解释**。页面显示成本乘 1.2，避免把 20% 加价率误读为 20% 毛利率。

## 与其他模块的关系和数据流

`Excel → parser.py::parse_excel → Product → agent.py::price_lookup_step → product_policy.py + db.py → PriceRecord.price(Decimal) → pricing.py::calculate_item_price → QuotationItem → agent.py::calculate_step → main.py 的 JSON → 页面`。网页抓价不在自动报价主流程。导出走 `task_id → main.py 从任务状态取明细 → exporter.py → Excel`；人工补价按 `item_id` 走 `confirm_prices → apply_manual_prices → calculate_item_price`。

本地新价格从 `db.py` 的 `price_decimal` 文本列读取，并标为 `decimal_text`。旧记录只能从原来的 `REAL` 列转成十进制，标为 `legacy_real`；网页适配器仍先抽取 Python `float`，标为 `external_float`；人工价标为 `manual`。`QuotationItem.price_source` 保存来源，`price_precision` 表明进入计算前的价格精度状况。这个标记是风险信息，不能替代来源凭证、型号核验或审批。

## 关键文件与函数：核心代码逐段读

1. **`app/config.py` 的规则常量**：`DEFAULT_PROFIT_RATE = Decimal("0.20")`、`MONEY_QUANTUM = Decimal("0.01")`、`MONEY_ROUNDING = ROUND_HALF_UP`、`PRICING_RULE_ID = "draft-cost-times-1.2-v1"`。它们集中定义现行草稿公式的参数与身份。后续改业务规则时应形成新版本并补回归用例。
2. **`app/pricing.py::as_decimal`**：对传入的十进制字符串、整数或旧代码中的浮点输入执行 `Decimal(str(value))`，拒绝布尔值、`NaN` 和无穷值。关键是后续计算都用 `Decimal`。如果一个数在更早的外部环节已经被截断，这个函数不能找回丢失的位数。
3. **`app/pricing.py::calculate_item_price`**：先校验加价率、折扣和成本价；成本缺失或为零时产生待人工确认项；有效成本按下面的顺序计算：

   ```python
   unit_price = (cost * (Decimal("1") + rate) * factor).quantize(
       MONEY_QUANTUM, rounding=MONEY_ROUNDING
   )
   total_price = unit_price * product.quantity
   ```

   返回的 `QuotationItem` 同时保留原始成本、单价、行价、规则 ID 和舍入方式。数量来自 `Product.quantity`，当前模型要求至少 1 个整数。
4. **`app/db.py::init_db`、`insert_price`、`_price_record_from_row`**：初始化时为旧表补 `price_decimal`、品牌、规格、单位、币种、来源凭证、有效期与核准标记。新价格以 `str(record.price)` 写入文本列。旧记录仍可读取并标注 `legacy_real`，但缺少合格元数据时不会自动用于报价；旧精度无法恢复。
5. **`app/agent.py::price_lookup_step` 与 `calculate_step`**：只有经 `eligible_price` 核对的人民币施耐德正价才写入 `price_source` 和 `price_precision`；其他行进入待处理。人工补价后来源标为“人工录价”；总价用 `sum(..., Decimal("0.00"))`。人工补价已改按 `item_id` 识别，同名行不会串价。
6. **`app/main.py` 与 `static/index.html`**：FastAPI 对旧上传字段 `profit_rate` 只允许 `0.20`；页面不再提供任意加价率输入。补价 JSON 用 `item_id → Decimal`；响应对报价项用 `model_dump(mode="json")`，金额输出为字符串。网页直接显示后端的人民币 `total_price`，输入成本价时发送文本，不在 JavaScript 中计算报价。
7. **`app/exporter.py::export_quotation`**：主报价页的金额单元格按 Excel 数字格式显示；“计算依据-内部”页以文本保留成本、加价率、折扣、单价、行价、来源、精度、规则、舍入方式及 `CNY`。Excel 数字单元格有浮点表示限制，因此十进制原文用于核对。导出仍含成本与加价率，**只能视为内部草稿**。
8. **`app/validator.py::validate_price_basic`**：负价现在能形成 `is_valid=False` 的核查结果，不再因 `PriceValidationResult.original_price` 的非负约束发生模型错误。范围和历史偏差仍只警告，不会阻断报价。

## 常见错误与排查

- **单价乘数量不等于行价**：核对是否走 `calculate_item_price`，检查 `MONEY_QUANTUM` 与 `MONEY_ROUNDING`；历史导出文件不会自动重算。
- **旧价格显示 `legacy_real`**：它来自旧 SQLite `REAL` 列。找原始供应商记录复核，再录入新价格；不要把转成 `Decimal` 理解为“恢复精度”。
- **网页价是 `external_float`**：抓取器目前用 `float` 抽数，且未进入主流程；不能自动作为人民币施耐德成本价。
- **金额接口字段由数字变为字符串**：客户端不要对这些字段用 JS `+` 汇总；使用响应中的 `total_price` 或让后端重算。
- **测试找不到 `app`**：在项目根目录用虚拟环境的 `python -m pytest`。
- **查到零价仍待确认**：`price_lookup_step` 将零价视为缺价，不能把 0 当成有效采购成本。

## 技术面试可能问

**为什么使用 `Decimal`，还需要规则 ID？** `Decimal` 保证按给定十进制规则复现计算；规则 ID 说明选了哪一版公式和舍入策略，二者分别解决“怎么算”和“按什么规则算”。

**是不是已经达到正式财务级报价？** 还没有。用户已指定成本乘 1.2，但税、折扣与舍入政策仍待企业确认；旧 SQLite `REAL` 价格和网页浮点价格需要复核，本机审批不能代替企业签核。

**为什么 Excel 主表仍写数字？** 报价员需要可排序、可计算的数字单元格；精确原文另存于内部依据页供核对。客户外发模板将另行设计。
