# 开发与教学规范

## 一个模块的固定节奏

1. **先核对现状和业务问题**：看入口、模型、调用方、相关测试；区别“代码已有”“设计文档提出”“企业已确认”。沿用现有结构能解决问题时不重构。
2. **先交付代码**：明确输入输出和失败条件，修改最小必要范围；金额使用精确的十进制表示与已确认的舍入规则，保存价格依据与计算过程；增加类型标注、配置、日志和边界异常处理。
3. **做有意义的验证**：运行相关单元测试和必要的端到端测试；说明通过项、失败项和未验证项。测试不得依赖真实客户资料。项目根目录用 `.venv/bin/python -m pytest -q`，因为直接调用 `.venv/bin/pytest` 在本机收集测试时找不到 `app` 包。
4. **最后写教程**：更新本目录对应模块，保留真实代码路径和关键函数；按“业务目标 → 为什么 → 数据流 → 逐段代码 → Python 基础 → 运行测试 → 排错 → 面试题 → 练习”组织。新概念先用白话解释，再给专业定义。标记“必须掌握”和“可以暂缓”。
5. **更新进度并汇报**：记录开发状态、教程状态、验证证据和待解决疑问。汇报功能、改动文件、测试及未验证项、教程链接、先读哪一节。

## 教程必须遵守

- 每段解释指向当前仓库的真实文件、函数或可复现行为；示例与正式代码不同要写清楚。
- 不把“使用 LangGraph”自动称为模型自主决策；当前报价主流程是固定规则工作流。
- 不把警告写成阻断，不把 SQLite 中建了表写成已经持久化任务，不把 `float` 和 `round` 写成财务精度保证。
- 不把预期技术栈当作现状。当前前端是原生 HTML/JS；只有业务需求和界面复杂度需要时才评估 Streamlit。
- 每篇明确哪些知识先学、哪些可以暂缓；面试回答只陈述自己能现场演示或从代码证明的能力。

## 完成定义

一个开发模块只有在**功能实现、适当测试、文档同步、进度更新、限制说明**都完成后，才标记为“已完成”。“教程已写”不等于“业务功能已验证”。企业定价口径、税、币种、审批、价格来源和有效期等需业务人员确认；未知就标为待确认。
