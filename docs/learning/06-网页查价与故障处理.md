# 模块 5：可选网页查价与故障处理

## 业务目标与为什么这样做

网页查价代码目前是**未接入自动报价的实验模块**。网络、网站结构、品牌和型号对应关系都会变化；现阶段缺少合格本地价时进入人工处理，不会用网页数字自动给施耐德产品报价。保留适配器与重试代码供后续有授权数据源时评估。

**概念**：适配器是把不同网站的操作包成相同接口。专业地说，`BaseScraper` 定义 `can_handle` 和 `search`，具体网站类分别实现。重试是暂时失败时再次调用；它不能修复选择器失效、登录缺失或型号不匹配。

核心技术及作用：可选 Playwright 驱动浏览器，适配器类负责网站差异，`retry_with_fallback` 处理抛出异常后的重试，日志留下故障线索。保持可选是因为外部页面稳定性和数据授权尚未验证。

## 文件、函数与数据流

实验调用路径是 `app/tools.py::search_web_price_tool → app/web_scraper.py::search_web_price_sync → search_web_price_async → WebPriceScraper.search_price → ZKHScraper / Alibaba1688Scraper`；`app/retry.py::retry_with_fallback` 包裹同步调用。`app/agent.py::price_lookup_step` **没有**调用这条路径，它只接受严格匹配的本地人民币价格。

## 核心代码逐段读

1. `web_scraper.py` 尝试导入 Playwright；未安装时 `PLAYWRIGHT_AVAILABLE=False`，`WebPriceScraper.__aenter__` 不启动浏览器，查价返回 `None`。默认 `requirements.txt` 没有 Playwright，所以这是可选能力。
2. `WebPriceScraper.search_price` 遍历适配器，`can_handle` 为真才创建页面；`finally` 中关闭页面。找到一个候选即返回 `PriceRecord`，包含来源、价格、置信度和抓取时间；当前没有保存网页链接到 `PriceRecord`。
3. 两个适配器根据固定选择器找价格文本，再用正则抽数字。选择器和页面结构可能改变；代码未验证结果属于同型号、同品牌、同单位商品。代码注释提到京东工业品，但实际注册的只有震坤行和 1688。
4. `search_web_price_sync` 在内部定义 `_search` 并用 `retry_with_fallback` 包裹；`max_retries=3` 表示首次调用之外最多再试 3 次。装饰器捕获异常并指数等待；若网站函数内部已经吞掉异常、返回 `None`，外层不会重试。
5. `tools.py::search_web_price_tool` 还有一层广义异常捕获，记录警告后返回 `None`。下一轮应区分可重试的临时网络故障与需要人工处理的业务不匹配。

## 必须掌握的 Python 基础

必须掌握：类和继承、`try/except/finally`、`None`、`async`/`await` 基本用途、装饰器包装函数、日志。可以暂缓：浏览器自动化细节、并发爬取、复杂正则和反爬策略。

## 运行与验证

可上传没有合格本地价的施耐德样例产品，观察进入人工确认；这验证的是主流程的价格缺失处理，**不是**网页抓价。网页实查需要额外安装 Playwright 和浏览器，且涉及网站状态；2026-10-21 未进行外部网页实测。现有 `pytest` 没有覆盖抓价模块。后续应优先寻找可授权、稳定的供应商接口或正式价格表。

## 常见错误与排查

- 总是进人工确认：先检查品牌、型号、本地价格的 CNY、来源、有效期和核准状态；安装 Playwright 不会改变当前主流程。
- 网页有价但结果不对：核对选择器命中的是哪件商品；目前没有严格核验型号、单位和品牌。
- 想重试却只调用一次：网站适配器可能把异常捕获成 `None`；`retry_with_fallback` 只对抛出的异常重试。

## 面试可能问

**网页价格可靠性怎样保证？** 当前不能保证，因此主流程不自动采用；以后需要来源链接、时间、施耐德产品属性核验和人工审批。**重试能解决哪些问题？** 临时异常可重试；业务数据错误不应重试。**当前是模型在选网站吗？** 不是，实验适配器按注册顺序调用固定网站。
