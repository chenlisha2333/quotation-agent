# 模块 5：角色审批、冻结版本与客户报价

更新日期：2026-10-21。本模块在“内部草稿计算完成”之后增加技术、采购、商务顺序审批。三个不同人员使用各自令牌批准后，系统保存一份不可覆盖的第 1 版报价快照，再从该快照生成不含成本、加价率和内部备注的客户 Excel。**这只是本地可验证的最小审批闭环**；企业身份系统、正式规则签核、税和商务条款仍需企业确认。

## 1. 业务目标：为什么草稿不能直接外发

原型内部 Excel 包含成本价和加价率，且“完成”仅表示计算结束。客户版必须先明确技术选型、采购成本和商务条款分别由谁核对，且发布后的内容不能被后续操作悄悄改写。因此本模块把“草稿完成”和“客户版本发布”分成两个状态维度：`status="完成"` 表示计算完成；`published_revision=1` 表示三阶段审批及规则版本闸门通过。

## 2. 核心技术及其作用

- **基于角色的访问控制（RBAC）**：简单理解是“每把钥匙只能开对应的门”。专业定义是把权限授予角色，再把角色授予用户。这里令牌对应 `technical`、`procurement`、`commercial` 角色；正式部署应换企业身份系统。
- **审批状态机**：简单理解是“必须按顺序盖章”。`APPROVAL_ORDER` 固定技术 → 采购 → 商务；不同阶段不能由同一人完成。
- **不可变快照**：简单理解是“发布时拍一张不能覆盖的照片”。`quote_revisions` 的 `(task_id, revision_no)` 是主键；第 1 版发布后不提供更新接口。
- **字段白名单导出**：客户 Excel 的每一列由 `export_customer_quotation` 明确列出，内部成本字段不会因为模型以后新增字段而自动流出。

## 3. 为什么选择这个方案

项目已有 FastAPI、SQLite 和内部 Excel 模板，不需要为最小审批闭环增加新服务。`QUOTE_APPROVERS_JSON` 从环境变量读令牌和角色，源码与示例文件不保存真实密钥。未配置令牌时，本机仍可学习草稿流程，但审批返回 503。配置令牌后，上传、查询、补价和导出等私有接口都要求有效令牌：技术看不到成本和销售金额，采购能看成本但看不到销售金额；只有采购能录入成本，只有采购或商务能导出含成本的内部草稿。

当前草稿规则 `draft-cost-times-1.2-v1` 尚未经企业确认。商务阶段额外要求 `QUOTE_APPROVED_RULE_ID` 与每一行的 `pricing_rule_id` 一致；缺失配置时发布会被阻止。只有企业实际确认公式、税和舍入规则后，才应设置该值。测试将它设置为草稿规则 ID，只证明技术流程可运行，**不代表企业已批准该规则**。

## 4. 与其他模块的关系和数据流

```text
已完成的人民币施耐德草稿（app/agent.py）
  → 技术令牌 + 审批意见
  → 采购令牌 + 审批意见
  → 商务令牌 + 审批意见 + 已批准规则 ID
  → app/db.py 同一事务保存任务、事件和 quote_revisions v1
  → app/main.py 从冻结快照读取
  → app/exporter.py 仅写客户可见列
```

`app/product_policy.py` 在审批和内部导出前再次校验施耐德、型号、人民币和正成本。人工补价只让草稿进入“完成”，不会自动替任何角色审批。`app/db.py` 的 `task_events` 记录审批阶段、操作人和意见；此“操作人”是令牌配置里的名称，尚不能替代企业实名审计。

## 5. 相关文件与关键函数

| 文件 | 函数或类 | 作用 |

| `app/auth.py` | `Approver`、`configured_approvers`、`authorize` | 读取令牌配置、核对身份与角色 |

| `app/db.py` | `save_task_snapshot`、`load_quote_revision` | 在事务中写任务、事件和发布版本；读取冻结版本 |

| `app/exporter.py` | `export_customer_quotation`、`_safe_excel_text` | 白名单 Excel 和文本公式防护 |

## 6. 核心代码逐段解释

第一段看 `app/auth.py`：`configured_approvers` 从 `QUOTE_APPROVERS_JSON` 读取数组，并用 Pydantic 检查 `actor`、`role`、`token`。`authorize` 比对 `Authorization: Bearer ...`，角色不对返回 403，令牌缺失或错误返回 401，审批尚未配置返回 503。`app/main.py::_task_response` 还按角色隐藏金额字段和可能包含价格的流程消息。令牌存在环境变量中，页面输入框只保留于当前打开的页面；不要把它写入 Excel 或提交到 Git。

第二段看 `app/approval.py`：`approve_quote` 每次都从数据库读取最新任务，确认草稿已完成、明细满足施耐德人民币规则，然后检查前面阶段是否已批准以及是否由不同人执行。商务阶段核对 `QUOTE_APPROVED_RULE_ID`。同一人重复发送完全相同的审批意见，函数返回原状态；不同意见不能覆盖原批准。这样使发布记录稳定。

第三段看 `app/db.py`：`save_task_snapshot` 在一次事务中写任务快照、`task_events` 和可选的 `quote_revisions`。如果其他请求已经更改任务版本，整个事务回滚。`quote_revisions` 只有插入和读取函数，没有更新函数。

第四段看 `app/main.py` 和 `app/exporter.py`：请求 `POST /export` 的 `format="internal"` 时导出成本和计算依据，供内部核对；`format="customer"` 时必须有商务令牌和发布版本，服务端从 `quote_revisions` 取冻结快照，然后只写名称、型号、规格、品牌、数量、单位、人民币单价和金额。`_safe_excel_text` 使以 `= + - @` 开头的产品文本按文字写入，避免 Excel 把客户输入当公式执行。

## 7. 必须掌握的 Python 基础

**必须掌握**：环境变量通过 `os.getenv` 读取、`list` 和 `dict`、`if` 条件、`set` 比较、异常与 HTTP 状态码、Pydantic 模型校验、函数参数的默认值。尤其要看懂 `approvals` 如何从空字典逐步加入三个阶段。

**可暂缓**：OAuth/OIDC、企业单点登录、密码库、HSM 和复杂审批规则引擎。本模块没有声称实现这些；正式部署前还需要它们或等效企业控制。

## 8. 实际运行与测试

在项目根目录运行：

```bash
.venv/bin/python -m pytest -q -p no:cacheprovider tests/test_approval.py
.venv/bin/python -m pytest -q -p no:cacheprovider
python run.py
```

本地演示审批前，先确认当前公式只是草稿规则。用**仅供本机测试**的不同令牌配置三个角色，例如在当前终端设置 `QUOTE_APPROVERS_JSON` 为包含三个 `actor`、`role`、`token` 的 JSON 数组，每个令牌至少 16 字符；再设置 `QUOTE_APPROVED_RULE_ID=draft-cost-times-1.2-v1`。实际客户报价前不能沿用这个演示确认，需先取得企业规则签核。浏览器页面可依次切换角色令牌，填写审批意见，最后点击“导出已发布客户报价”。也可使用 `/docs` 的 `POST /tasks/{task_id}/approve/{stage}` 和 `POST /export`。

测试使用临时数据库、虚构令牌和虚构产品型号；它验证代码行为，不验证真实施耐德选型、真实采购价或商务条款。

## 9. 常见错误和排查

| 返回或现象 | 原因与处理 |
|---|---|
| 401 | 配置了审批令牌，但没有填令牌或令牌错误。检查当前页面输入值和请求头。 |
| 403 | 角色和审批阶段不一致，例如采购令牌审批技术阶段。 |
| 503 | 未配置令牌，或 `QUOTE_APPROVERS_JSON` 格式无效。 |
| 409 顺序错误 | 先做技术，再做采购，最后商务；每阶段填写意见。 |
| 409 规则未确认 | `QUOTE_APPROVED_RULE_ID` 缺失或与报价项规则不一致；先完成真实业务确认。 |
| 客户导出 409 | 还没有保存三阶段审批的发布快照。`完成` 只是内部草稿状态。 |
| 服务重启后页面丢状态 | 在“恢复已有任务”输入任务 ID；任务和审批保存在 SQLite。 |

## 10. 技术面试可能问

1. **为什么客户导出要从冻结快照读？** 防止任务当前状态后来改变，让同一版本号导出不同内容。快照中虽保留内部成本供追踪，客户模板只取公开列。
2. **为什么审批和发布版本必须同一事务？** 否则可能出现“已显示发布，但找不到版本”或“版本存在，但没有审批事件”。
3. **当前权限能用于企业生产吗？** 不能。环境变量令牌适合本机演示，缺少企业身份集成、令牌轮换、实名审计、细粒度成本权限和部署安全控制。
4. **怎样防止原型公式生成正式报价？** 商务发布检查 `QUOTE_APPROVED_RULE_ID`；未配置或不匹配时拒绝。这个配置只能表达操作者的确认，真正的公司规则仍需要外部签核证据。
