# 17 只读产品资料检索的离线评测

## 业务目标：先知道“检索有没有找对”

只读助手会把检索到的产品事实交给模型回答。模型最终回答好不好，不能只看几条手工演示。本模块先把可重复的底层问题固定下来：给定一条问题，检索返回了预期来源吗？对未知型号、参数冲突和无关问题，是否保持空结果？

当前评测集是 10 条人工编写的**合成固定案例**，不是客户问题、生产数据或业务验收集。它只评估 `app.knowledge.search_knowledge()` 返回的产品来源 ID，不调用模型，也不评估答案内容。

## 核心技术及指标含义

**必须掌握：**

- `Exact Match`：实际来源 ID 集合与标注集合完全相同。此处不区分排序。
- `Recall@k`：所有有答案案例里，前 k 个结果覆盖的预期来源数量 / 预期来源总数。它不惩罚多出的错误来源，因此要和 Exact Match 一起看。
- `abstention_recall`：无答案案例中，检索确实返回空结果的比例。
- `false_positive_rate_on_no_answer`：无答案案例被错误返回任一来源的比例。
- 逐例 `error`：区分漏掉预期来源、错源、无答案误命中和多/漏来源，便于定位修改。

这些指标是对这 10 条固定合成案例的计数。即使结果为 100%，也只说明这组回归用例通过，不能推断真实业务问题表现。召回率不衡量生成回答的事实正确性；工具选择、引用是否覆盖答案、模型拒答和权限隔离仍需单独测试。

## 数据流与安全限制

`tests/fixtures/synthetic_knowledge_eval.json` → `load_dataset()` 检查唯一 ID、问题长度和 `data_class=synthetic` → `evaluate_dataset()` 调用词项检索 → 输出 JSON 报告。工具限定接受明确标记为 `synthetic` 的数据，避免误把含客户信息的业务集当作本地演示文件传入。

该工具不读数据库、不请求外部模型、不更改任务。当前检索资料在 `data_sources/schneider_products.json`，不能据此认定为中国区批准目录。施耐德中国区资料在 `data_sources/schneider_cn_product_master.json` 中仍为待审核草稿，与本评测和报价准入分开。

## 相关代码逐段解释

1. `load_dataset()` 负责读取 JSON 并校验数据类别、案例结构、唯一 ID、查询长度和来源 ID 列表。
2. `evaluate_dataset()` 对每条问题调用 `search_knowledge(query, limit=k)`，只保留稳定的来源 ID 用于比较，不把模型回答混入结果。
3. `_error_category()` 把集合差异转成可读类别。新增失败案例时，可以先看逐例输出，而不只盯着一个汇总比例。
4. `main()` 输出机器可读 JSON，命令行可保存重定向结果供复核。当前没有自动覆盖历史报告或上传数据的行为。

## 运行方式

在项目根目录运行：

```bash
.venv/bin/python -m app.knowledge_evaluation
.venv/bin/python -m app.knowledge_evaluation --k 1
.venv/bin/python -m pytest -q -p no:cacheprovider tests/test_knowledge_evaluation.py
```

预期报告包含 `sample_count=10`，以及每例预期/实际来源和错误类别。第二条命令会改变 Recall@k 的截断范围，但不会改变数据集。评测失败时先检查检索输出，再检查期望来源是否来自当前事实文件；不要为了让数字好看而改标签。

## 后续如何扩成真正评测

拿到数据许可后，由业务/技术评审人整理中文问题、可引用答案证据、无答案问题和越权问题；每例保留来源文档与版本、人工裁定和不确定项。按客户/文件/时间等可能重复的来源分组划分开发集与封存验收集，避免同一询价内容变体同时进入两边。真实模型评测应另外记录模型与提示版本，并检查答案事实、引用覆盖、拒答、工具选择和越权行为。

没有授权、真实标注集或模型版本信息时，不报告真实业务指标，不把本合成评测率写成简历准确率。

## 面试可能问

**这 100% 代表什么？** 仅表示 10 条冻结合成问题与当前来源 ID 期望一致，不代表真实业务准确率。

**为什么 Recall@k 之外还要看 Exact Match？** 召回只关注期望来源有没有出现；错误额外来源可能让模型混淆，所以需要检查结果集合是否完全符合标注。

**这是 RAG 的完整评估吗？** 不是。它只测检索层；生成答案忠实度、引用完整性、工具选择、拒答和权限要用真实模型/模拟协议分别评测。
