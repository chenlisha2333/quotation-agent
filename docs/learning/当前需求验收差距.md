# 当前需求与 PRD 验收差距

更新日期：2026-10-28。以[PRD](../PRD.md)为当前需求基线，对照上级 `项目需求总结_v2.md` 的长期方向，本项目现已形成可测试的**人民币施耐德报价技术闭环**：Excel 上传、严格价格准入、人工补价、来源与原件哈希追溯、任务恢复、技术/采购/商务本机审批、冻结第 1 版与客户字段隔离。它仍是原型，不能据此声称企业已正式使用或完成整个 PRD。

| PRD 能力 | 当前证据 | 下一步需要的真实输入或工作 |
|---|---|---|
| 至少 5 类真实询价格式 | 现有混合品牌演示表和三款施耐德候选型号示例表；均不是真实客户询价 | 提供 5 类脱敏真实文件及人工确认的标准字段；再做解析映射与冻结验收集 |
| 施耐德产品主数据与候选匹配 | 示例表的三个型号有官方产品页；程序仍只检查品牌文本和型号是否填写，不证明客户选型正确 | 经许可的完整施耐德产品目录、型号属性、别名与技术人员确认记录 |
| 供应商价格版本、含税/交期/阶梯价 | 现有本地价格表有来源、有效期、币种和核准标记；缺税、交期和阶梯价格规则 | 脱敏供应商价格表和采购确认的字段口径、审批路径 |
| 企业定价和异常阈值 | 用户指定草稿成本乘 1.2，`draft-cost-times-1.2-v1` 可重复测试，但税和正式规则尚未签核 | 税、运费、舍入、最低利润及异常审批条件的书面确认 |
| 报价修订版本和发送记录 | 已发布第 1 版不可覆盖；尚无变更生成第 2 版与发送状态 | 客户议价/技术变更样例、版本与作废流程、发送方式和责任角色 |
| 成本与询价原件来源追溯 | 报价快照保存价格记录 ID、凭证标识、有效期、规则 ID；任务保存询价文件 ID/扩展名/SHA-256；人工补价标注待采购凭证 | 采购凭证审核、文件备份/访问/留存/删除策略；哈希仅用于完整性核对 |
| 企业身份、审计和部署 | 本机令牌、SQLite 事件、角色字段隐藏与本地监听 | 企业账号、权限、备份、保留期限、并发与安全要求；正式环境验收 |
| CAD 一个柜型、5–10 种元器件 | 示例表记录三款官方产品的外形尺寸/开孔线索；没有 CAD 代码、柜型、安装孔位/净空或工程师批准图纸 | 一个柜型的安装板尺寸与约束、5–10 种经核对的施耐德元件安装数据、工程师批准的案例与判定标准 |
| 受控 AI 抽取和候选匹配 | 已有基于六款真实施耐德型号官方资料的检索与四个只读工具；问答仍不负责询价抽取、正式选型或定价；报价主流程是确定性工作流 | 经许可的完整产品目录、真实非结构化询价、字段级人工答案和模型使用授权；先做离线评估再扩大 |
| Word 报价与本机容器运行 | 内部和冻结客户版 Word 已有内容测试；Docker 配置已写但本机未启动 | 企业 Word 模板、目标办公环境中文排版、Docker 实机验证与部署方案 |
| 可写入简历的效果指标 | 101 项自动测试证明当前代码路径；T05 评测器仅用合成数据完成工具测试，没有人工基线或企业验收 | 获准的脱敏冻结集、人工报价结果、耗时基线、错误分类及业务人员签核 |
| 产品主数据 | 已有追加式版本模型、5 条中国区官网公开资料草稿、显式导入器和精确候选查询测试 | 公司数据使用依据、技术审核记录、目录完整性、别名/替代关系核实；报价主链接入与业务验收 |

## 下一轮实施顺序

1. 拿到真实询价与产品资料后，先建立脱敏冻结集和产品主数据，检验施耐德型号归属，扩展解析和价格模型。
2. 企业确认定价、税和审批规则后，将原型规则升级为带版本的正式规则，并在冻结集上与人工结果逐项对照。`QUOTE_APPROVED_RULE_ID` 不能单独充当业务签核证据。
3. 按真实变更案例实现报价第 2 版、作废和发送记录，再接入企业身份与正式审计。
4. 取得柜型、尺寸和工程师批准的图纸后，单独启动二维 CAD MVP：先做确定性布局和边界/碰撞/间距/BOM 校验，再考虑受控 AI 修复。

用户阅读教程时可先从[学习进度](学习进度.md)找到已实现模块；本表用于区分“代码已经做了什么”和“企业还须提供什么证据”。
